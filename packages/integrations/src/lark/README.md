# Lark integration

The package exports its public API through `src/index.ts`; the barrel contains no implementation.

- `account/`: account schema, parsing, account CLI service, and root Actor.
- `mail/`: mailbox/message models and parsers, mail-only CLI service, mailbox polling and message Actors.
- `im/service/`: `chat-service.ts`, message models, polling and date helpers.
- `im/config.ts`: IM configuration schemas, defaults and validation.
- `im/summary/`: rolling summarizer, summary gate, work orchestration and Agent admission queue.
- `im/`: ContextSession state, IM and Chat Actors.
- `shared/`: bounded/abortable CLI execution, response parsing and profile capture identity.
- `config.ts`, `integration.ts`: root configuration and Effect Layer composition.

`LarkChatService` owns remote IM queries through an Effect service. `searchMessages({ start, end, query?, excludeMuted? })` follows all pages within a fixed window, validates and normalizes messages, deduplicates by chat/message ID, and returns ordered batches per chat. `getChatSettings(chatIds)` queries per-user mute settings in batches of ten, rejecting incomplete, duplicate or unrelated results. Search includes muted chats by default; polling explicitly excludes them. `LarkChatService.make(run)` accepts an Effect transport for tests; its live Layer reads the configured profile and adapts the abortable CLI once. Transport failures use `LarkCliError`; invalid inputs/responses use `LarkChatQueryError`.

`pollChats` composes the service with fixed windows, one-minute overlap and today's Beijing midnight as the startup lower bound. Continuous polling can finish the previous day's tail. Polling defaults to fifteen minutes after completion; startup catch-up uses consecutive one-hour windows. Actors consume Effects directly. Public `list_chats`, `summary` and `messages` commands continue reading local Context evidence; remote search does not silently replace their retained-window contract.

IM persistence uses core's [ContextSession](../../../../docs/context-session-design.md). Chat and admission Sessions are continuous; retrieval coverage has explicit daily partitions. Infra uses the host's resolved durable root and Pi Documents. Messages are keyed by source ID; ordinary changes mutate individual keys. Public messages are sorted by source time and ID. The Channel awaits durable Chat acknowledgements through `pipeToSelf` before advancing coverage. Startup restores all previously accepted pending evidence, including prior-day work, without backfilling missing historical retrieval intervals.

The Actor/service boundary follows Goals:

- `channel-actor.ts` owns polling slots, child Actors, asynchronous ingress acknowledgements and timers. `channel/state.ts` owns ContextSession transitions and retrieval coverage; `channel/retrieval.ts` owns interval merging.
- `chat-actor.ts` owns one in-flight workflow, incoming-change tracking and generation checks. It has no local summary queue or batching timer. Its Behavior-scoped `ChatState` owns accepted evidence, ingestion receipts, a date-bounded flush and atomic summary commits.
- `summary/work.ts` owns the System One gate, in-memory deferrals, bounded chronological batches and Effect retry schedules. An acknowledged mailbox read selects the latest evidence after shared admission; each successful batch is committed through the mailbox. Model execution never holds a storage transaction.
- `summary/summarizer.ts` owns the prompt, reference validation and required `save_summary` result tool. AgentRunner executes with Effect callbacks and a two-minute timeout.

A completed summary, conditional deletion of its exact input versions, receipt cleanup and durable Context event commit together. Edits received during execution remain pending. `Flush(date)` forces evidence only through that date; newer arrivals resume ordinary assessment after it is covered. An unchanged summary clears covered evidence without screening again. Public views expose chat identity and summary while keeping receipts and retrieval boundaries private. The same view derives the chat description from its current name and purpose. Acceptance normalizes sender evidence before persistence and fingerprinting. Retired receipts are pruned only behind the durably advanced retrieval cursor and its replay overlap; pending evidence retains its receipts.

The Lark integration constructs one shared `ImAgentQueue` for all Chat Actors, defaulting to ten seconds between starts and two concurrent runs. Its Effect FIFO Queue serializes dequeue and start-time persistence. Cancellation releases queued/running work; failures and defects reach the requesting Actor without retiring workers. `summary.maxMessages` defaults to 200. Larger accumulated input bypasses the gate and uses separately admitted chronological batches. Recognized capacity errors halve the batch; transient failures retain it and retry up to three times, thirty seconds apart, releasing capacity before waiting. Other failures stop the cycle with evidence retained. Gate deferrals, retry budgets and errors are not persisted; restart reassesses accepted evidence with a fresh budget. Successful midnight coverage flushes prior-day pending evidence. See [IM summary design](../../../../docs/im-summary-design.md) for recovery and retention boundaries.

IM callers decode the schemas in `im/config.ts` directly; there is no separate policy parser. `LarkConfig.layer` reads typed `contexts./lark` settings. `LarkIntegration.layer` constructs internal services, registers views and activates through AsterRuntime. Readiness waits for this activation's initial catch-up. Context registry dependencies are shared with the runtime, and Behavior closure revokes Session handles. Tests use fake transports/models, real Actors, Deferred and TestClock; storage tests use temporary directories.

Mail polling uses `mail +triage --filter` with an inbox `time_range`, fetching every page with a fixed filter and page size. Search timestamps use whole-second ISO 8601 with an explicit UTC offset, as required by the search API; the start rounds down and the end rounds up to retain boundary messages. Startup replays only today in Beijing time, in serial one-hour windows; subsequent polls overlap the last successful window by one minute. The existing mail `pollIntervalMs` controls the delay after catching up (30 seconds by default). The 100-item page size is not a limit on the window's total mail count. Missing/repeated pagination tokens and incomplete message fetches fail the window without advancing its cursor.

The mailbox keeps its cursor private and volatile. Restart replays today and deduplicates against persisted email Contexts rather than discarding the first inbox listing. Continuous polling can finish the previous day's tail across midnight. Each message Actor acknowledges `SetEmail` only after its Context commit; the mailbox awaits acknowledgements through `pipeToSelf` before advancing. Shutdown interrupts retrieval and pending acknowledgements. Tests in `packages/integrations/test/mail-window.test.ts` and `apps/local/test/mail-poll.test.ts` cover pagination, overlap, recovery, and publication ordering with fake transports and `TestClock`.
